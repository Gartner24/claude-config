# Local audit of /design as it exists today

Source: `/home/santiago/claude-config/commands/design.md` (35 lines), symlinked to
`~/.claude/commands/design.md`. Setup doc: `~/claude-config/DESIGN-PIPELINE.md`.
Duplicated as a condensed rule inside `~/.claude/CLAUDE.md` ("UI / design work - pipeline rule").

## Finding 1 - two of the eight steps are dead, not skipped

This is the root cause behind "sometimes it skips some steps". The model is not only
being lazy - the steps point at things that cannot run.

- **Step 3 (Source, `magic` MCP / 21st.dev)** - the MCP fails to connect this session:
  `Not authenticated - your API key is missing or was reset`. `~/.claude.json` has exactly
  one global MCP server configured, `magic`, and it is the broken one. So the single
  component-sourcing step in the pipeline is currently a no-op on every run.
- **Step 5 (Assets, `nano-banana`)** - requires `GEMINI_API_KEY`. Not set in the
  environment, not in `~/.zshrc`, not in `~/.profile`, not in `~/.claude/settings.json`.
  The skill has never been runnable on this machine.

## Finding 2 - `dataviz` does not exist

Step 5 says: "Any chart, graph, dashboard, or stat tile: read `dataviz` before writing the
first line of chart code." There is no `dataviz` skill in `~/.claude/skills/`, in
`~/claude-config/skills/`, or in any installed plugin cache. Dangling reference.

Counter-check: `frontend-design` (step 4) is NOT missing - it resolves through the

## Finding 3 - image generation already exists three times and works zero times

The user believes Claude cannot generate images. The real situation is that three
separate, independently-written paths exist in this config, each demanding a different
API key, none of which is set:

| Path | File | Backend | Key it needs | Set? |
|---|---|---|---|---|
| `nano-banana` skill | `skills/nano-banana/scripts/generate_gemini.py` | Gemini image model | `GEMINI_API_KEY` | no |
| `impeccable` internal | `skills/impeccable/scripts/generate-image.mjs` | OpenAI `gpt-image-2` | `OPENAI_API_KEY` | no |
| `packshot` skill | `skills/packshot/SKILL.md` | Nano Banana 2 via FAL | `FAL_KEY` | no |

Also checked and unset: `GOOGLE_API_KEY`, `REPLICATE_API_TOKEN`, `UNSPLASH_ACCESS_KEY`,
`PEXELS_API_KEY`, `RECRAFT_API_KEY`.

Consequence: the fix is not new capability. It is one key plus one entry point that the
three existing paths hang off, so the design pipeline stops silently no-op-ing its asset step.

`nano-banana` also points at deep-reference files under `~/Downloads/temp/`
(`master_prompt_reference.md`, `Nano Banana 2.md`) - a user Downloads folder is not a
durable location for a skill dependency.

## Finding 4 - the Tailwind hole is structural, not a missing branch

Step 3 is the only component-sourcing step and it ends with "Skip this step if the stack
is not React/Next + Tailwind." Nothing replaces it. For Astro, Vue, Svelte, Angular,
plain HTML/CSS, Django/Jinja, Blade, ERB or WordPress the pipeline goes
direction -> (nothing) -> assemble, and "assemble" with no sourced components means
hand-rolling from zero, which is exactly the mode that produces generic output.

Note the locked direction is also expressed in Tailwind terms downstream. The portable
form of a direction is tokens (CSS custom properties), not utility classes - see research C.

Partial mitigation already present: `ui-ux-pro-max` advertises 13 stacks including Vue,
Svelte, SwiftUI, React Native and Flutter, so step 1 is already stack-aware while step 3
is not. The pipeline narrows after the one step that was general.

## Finding 5 - nothing in the command produces evidence that a step ran

All eight steps are prose bullets. There is no todo list, no per-step artifact, no state
file, no final table of what ran. Step 7 literally contains the string "Never skip this
step" and it still gets skipped, which is direct evidence that emphasis-as-enforcement
does not work here. There is no mechanism by which a skipped step becomes visible to the
user afterwards.

Duplication makes this worse: the pipeline exists twice (the command file and the
CLAUDE.md rule) with slightly different wording - the CLAUDE.md copy has 5 steps, the
command has 8. The CLAUDE.md copy omits the register lens, the assets step and the
conversion step entirely.

## Finding 6 - no reference-sourcing step at all

Step 1 can run `design-dna` only when the user supplies a reference. If the user supplies
none, the pipeline picks from `ui-ux-pro-max`'s internal catalog of 67 styles and never
looks at a real shipped product. No Mobbin, no gallery, no screenshot of a real
competitor. The Chrome MCP that could fetch one is connected and unused by this pipeline.

## What this audit says the rebuild must do

1. Repair or replace the two dead steps before adding anything new.
2. Delete or write the `dataviz` reference.
3. One asset entry point over the three existing generators, one key to set.
4. A real non-Tailwind branch, with tokens as the portable direction format.
5. Per-step evidence, and a closing table marking each step RAN or SKIPPED-because-X.
6. A reference-sourcing step that looks at real shipped UI before proposing anything.
7. Collapse the duplicate pipeline in CLAUDE.md into a pointer at the command.
