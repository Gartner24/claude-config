# When to switch on (beats skill text)

Source: docs/briefs/context-trim-and-all-chats.md Part 2, docs/briefs/retire-runner-features.md rows 10, 18, 20, 28, 31, 32, 38, 42, 44, 46, 59. Owner decision: a feature that used to run in some chats is a rule in every chat. It switches itself on when its condition is true; nothing is set per chat.

- App start and browser verify (10). When: the repo's `AGENTS.md` has `app start` and `app url`, and a `/check verify` runs. Do: start the app with `app start`, drive it at `app url` with the chrome-devtools MCP, then stop what you started. A repo without both lines: no browser verify.
- Keep awake (28). When: the owner says "I am leaving" or "finish it". Do: run `systemd-inhibit --what=sleep:handle-lid-switch --why=claude sleep 8h` in the background, so the lid can close.
- Parallel features (31). When: the owner says "do these features", or two or more features are ready. Do: one `isolation: worktree` agent per feature, never two whose spec `**Paths:**` overlap (compare the globs by hand; `spec-paths --overlap NNNN NNNN` does not exist yet, see the list below), never two apps on one port. Pick model and effort per agent (effort at most high, at least low; haiku for lookup, sonnet for edits and review, opus for design and hard work). Writing the scope rows and the `/architect` questions for all of them comes first (`rules/runner-handoff.md`; the build starts in a fresh chat per `rules/fresh-chat-after-architect.md`). Gates before each extra agent: see the 32 line below.
- Start gates (32, not built). Intended: a new agent starts only above 4.5 GB free memory (`MemAvailable`) and under 80% of the 5 hour use; each suite gets `nproc/(agents+1)` cores. Until the script exists, check `MemAvailable` by hand before each extra agent.
- Self-merge checklist (38). When: your own or a personal repo only, never a work or client repo, and you are about to merge a PR. Do: merge only when the scope's verify and test boxes are ticked, the repo's own suite passes on the PR head, and all checks are green for that head (a PR with no checks yet: wait 10 minutes for a first one). Merge with `gh pr merge --squash --match-head-commit <sha> --delete-branch`, one PR at a time.
- Review comment loop (42). When: a PR you opened has open review comments. Do: `/loop 10m` with `sentry-skills:iterate-pr`. Fix clear comments one commit each, reply with the sha, ask the owner before declining one, stop after 3 rounds. Sorting of findings stays in `rules/review-fix.md`.
- Foreign change check (44). When: the branch has commits by someone else. Do: list the changed files that can run code - `.claude/`, `CLAUDE.md`, hook managers, package scripts, build and test config - and ask the owner before running tests or hooks there. For claude on that code use `--setting-sources user --strict-mcp-config`.

- 20 issue reread: when the scope header says `Source of truth: issues` or `mixed`. Show the linked issue's changes since the spec's accept date before each step.
- 31 and 32 helpers: `spec-paths --overlap NNNN NNNN` and a start-gates script (free memory, 5 hour use, cores per suite), called before each extra agent.

- 59 scope marker warnings: when a scope file is read or written. Warn on near miss markers and old "waits on" wording (lives with the moved scope parser).
