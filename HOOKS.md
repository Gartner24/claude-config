# Hooks

Most hooks in `settings.json` are auto-managed - they come from gstack, jjstack, or claude-mem,
and reinstalling those frameworks restores them. Two are hand-written and live in this repo
(`hooks/block-destructive.sh`, `scripts/chroma-reaper.sh`); those you do maintain.

## Where each hook comes from

| Hook file | Source | Purpose |
|-----------|--------|---------|
| `gsd-check-update.js` | get-shit-done-cc | Checks for gstack updates on session start |
| `gsd-session-state.sh` | get-shit-done-cc | Injects project state reminder at session start |
| `gsd-context-monitor.js` | get-shit-done-cc | Monitors context usage after Bash/Edit/Write/Agent/Task |
| `gsd-phase-boundary.sh` | get-shit-done-cc | Detects .planning/ file writes to track phase progress |
| `gsd-prompt-guard.js` | get-shit-done-cc | Guards against prompt issues on Write/Edit |
| `gsd-read-guard.js` | get-shit-done-cc | **NOT WIRED** - present in `~/.claude/hooks/` but referenced by no entry in settings.json |
| `gsd-workflow-guard.js` | get-shit-done-cc | Enforces GSD workflow rules on Write/Edit |
| `gsd-validate-commit.sh` | get-shit-done-cc | Enforces Conventional Commits format on Bash |
| `claude-mem-install.sh` | claude-mem | Ensures claude-mem node_modules are installed |
| `auto-approve-safe.sh` | jjstack | Smart permission gate using Claude Haiku for safe ops |
| `error-detector.sh` | jjstack | Records failed Bash commands to JSONL log |
| `injection-guard.sh` | jjstack | Scans Write/Edit content for prompt injection in .md files |
| `mcp-reconnect.sh` | jjstack | Reconnects MCP servers on tool failure. Not symlinked into `~/.claude/hooks/` - settings.json calls it at `~/.claude/skills/jjstack/hooks/` |

| `chroma-reaper.sh` | **hand-written** (this repo, `scripts/`) | Background reaper started once per session; keeps claude-mem's chroma processes from piling up |

## Key behaviors these enable

**`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE: 100`** - Autocompact is effectively off; context runs to
full before Claude summarizes. Maximum context retention, at the cost of a hard stop instead
of a graceful compact.

**Model** - not pinned in settings.json. The `model: opus[1m]` pin documented here was
removed in commit 82fcf80; the model is chosen at runtime (`/model`, or the session default).

**`permissions.defaultMode: auto`** + **`skipAutoPermissionPrompt: true`** - paired with
`auto-approve-safe.sh` below. The auto-mode classifier still hard-blocks some things
(`git reset --hard`, `git merge` in some shapes); when that happens, run it yourself with the
`!` prefix or use a narrower command.

**`block-destructive.sh`** - the backstop that survives auto-mode: any `rm -rf` aimed at an
absolute, `$HOME`, parent (`..`), or wildcard path is refused outright and must be run by hand.

**`auto-approve-safe.sh`** - Uses Haiku to evaluate permission requests and auto-approve
safe operations. Reduces permission prompts for read-only and low-risk tool calls.

Modified from jjstack default: Haiku prompt tightened to rate HIGH only for truly
destructive/irreversible commands (rm, force-push, drop database, system package installs,
exfiltration). MEDIUM is now auto-approved alongside LOW. Only HIGH defers to the user.
This means ~90% of prompts are silently approved without interrupting the session.

> The modification lives inside the jjstack git checkout, so a `git reset`/`merge` during a
> jjstack upgrade wipes it. The diff is kept in this repo at
> `hooks/jjstack-auto-approve-safe.patch` (regenerated by `sync.sh`). Upgrade procedure:
> `git stash` -> `git merge --ff-only origin/main` -> `git stash pop` -> `./setup`.

**`gsd-read-guard.js`** - shipped by get-shit-done-cc and present on disk, but wired to no
hook entry in settings.json, so it does not run. The read-before-edit enforcement you see
comes from the harness itself, not from this file.

**Status line** - Powered by `jjstack/bin/statusline.sh`. Shows project state in the terminal.

## Restoring on a new machine

Hooks are file paths hardcoded to `/home/santiago/`. On a new machine:
1. Install jjstack (installs gstack + creates hook symlinks)
1b. Install get-shit-done-cc - it ships the 8 `gsd-*` hooks, and settings.json
    references 6 of them. Without this step the session starts with dead hook
    entries. Pin 1.34.2; see the pin note in SKILLS.md.
2. Install claude-mem plugin
3. Copy `settings.json` and update the `/home/santiago/` paths to match the new username/home
4. `settings.local.json` can be copied as-is
