# MiroFish (666ghj/MiroFish) - research report, 2026-10-15

Sources: cloned repo at scratchpad/clones/mirofish (HEAD 7657031, 2026-10-02, never run), GitHub API, HN Algolia, r.jina.ai. Firecrawl hit its free rate limit; exa/tavily not needed.

## Facts
- Stars 79.5k, forks 12k, 147 open issues, created 2025-11-26, last push 2026-10-01 (GitHub API). License AGPL-3.0 (LICENSE, pyproject). Backed by Shanda Group ("strategic support and incubation from Shanda Group", README). Languages: README.md (English) + README-ZH.md. No docs/ dir. README-EN.md (linked on HN) no longer exists.
- What it is: Flask backend + Vue frontend. Upload seed docs (pdf/md/txt, 50MB cap), describe a question. It builds a knowledge graph (Zep Cloud), generates personas from graph entities, runs a Twitter-like and Reddit-like simulation with the OASIS/CAMEL-AI engine (camel-oasis 0.2.5, camel-ai 0.2.78), then a ReportAgent (ReACT with tools, max 5 tool calls, 2 reflection rounds) writes a report; you can chat with any simulated agent.
- Keys: LLM_API_KEY/BASE_URL/MODEL_NAME (any OpenAI-format API; README recommends Alibaba Qwen-plus; code default gpt-4o-mini) and ZEP_API_KEY. Config.validate() rejects ZEP_API_URL: "MiroFish only connects to Zep Cloud". README: "High consumption, try simulations with fewer than 40 rounds first". Zep free tier "sufficient for simple usage".
- Cost: no published per-run figure. Each agent acts every round by an LLM tool call; N agents x rounds x 2 platforms. Expect many thousands of calls per run. Not measured by me.
- Local / own subscription: LLM side is OpenAI-compatible only, so Ollama/vLLM work in principle. Issue 847: with vLLM lacking tool calling, "every agent action fails silently and the simulation completes nearly empty" (agents need tool_choice auto). Issue 58: Ollama timeouts. Zep is hard-required cloud; local replacement PRs are open/unmerged (650 SQLite fallback, 634 JSON storage; 741 closed). A Claude subscription cannot be used: no Anthropic API support, subscription OAuth is not an OpenAI-format endpoint. Would need an Anthropic-to-OpenAI proxy plus API billing.
- Accuracy evidence: none published by the project. Demos are Wuhan University opinion simulation and a Dream of the Red Chamber ending. Third-party calibration rig (zzvimercm-git/mirofish-calibration, HN Show, 1 point): on a crude swarm proxy, n=5 synthetic cases, qwen2.5:7b, "a single LLM ties a crude multi-agent swarm", and "a single LLM wins clearly" on which objections surface (recall ~98% vs ~70% in TL;DR; table shows 84% vs 71%). It explicitly says it is NOT real MiroFish. Issue 17: results depend on model; issue 751: persona population differs every run for same input.
- HN: several submissions, 1-5 points, 0 comments. No real HN discussion. Hype is mostly GitHub stars / Chinese social.
- Quality issues in open tracker: silent failures (847), report hallucinating tool results (529, 599), runs fail late with no resume (688), Zep rate limits kill report step (261).
- Security: backend binds 0.0.0.0 by default (run.py FLASK_HOST), CORS "*" on /api, no auth, hardcoded SECRET_KEY default, docker-compose publishes 3000 and 5001 to all interfaces. Open issue 489 (path traversal via platform param, SQLite read); at HEAD simulation.py:2160-2169 and 2237-2247 still build f"{platform}_simulation.db" from request.args without whitelist (I did not run it). Auth/path PR 605 is open, unmerged. Docker image ghcr.io/666ghj/mirofish:latest is unpinned. Deps: PyMuPDF, flask, openai, zep-cloud, camel stack (large).
- AGPL: running it internally for your own research is fine. Obligations trigger on distribution or on offering a modified version to users over a network (must offer the source of your modified version). Using unmodified MiroFish privately to produce a report for a client does not hand the client the software; the report output is not covered. Do not embed it in a client site/SaaS or host a modified copy for clients without releasing source. Not legal advice. Also a company's SaaS (user's employer) should not take it in without legal review.

## Verdict
Interesting demo, high star count, no evidence it predicts anything beyond what one good LLM prompt gives. Immature (v0.1, silent failures, security holes), cloud-locked (Zep), cost unbounded, and cannot ride the Claude subscription. Not worth installing for client work now.

## Best concrete use for this user (if any)
Persona-based reaction testing of a landing page or campaign copy for a client: but a Claude Code subagent loop (10-20 personas drawn from the client's real reviews, one pass, plus a single-LLM baseline) covers it on the subscription with no new infra. If wanting to see MiroFish itself: a sandboxed, throwaway container, Qwen-plus or a cheap model, 10-20 rounds, small seed doc, with a spend cap, as an hour-long experiment, not a client deliverable. Never present output as a forecast to a client.

## Risks
Wasted API spend; false confidence in "predictions"; client data sent to Zep Cloud and a third-party LLM (confidentiality/DPA); open unauthenticated API on all interfaces; AGPL if hosted; project may churn (147 open issues, one core maintainer team).
